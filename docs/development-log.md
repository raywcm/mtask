### 本次设计决策

1. 每任务一个独立 Broker，同一二进制重新执行；无需全局 daemon。
2. Broker 持有 PTY 和任务生命周期，连接只持有控制权。持续读 PTY 的循环不由 attach 请求的 context 驱动。
3. 单一可写控制端，有界队列；慢客户端断开，不阻塞应用，不在丢失字节后继续同一条画面流。
4. Unix Socket 上使用有版本的二进制帧；输入/输出载荷保持原样。认证与协议处理器留待 A1。
5. CLI/TUI 共用 service；TUI 退出并恢复终端后，才可由 attach 接管。当前只完成选中 ID 的边界。
6. `spec.json` 与 `runtime.json` 分开，避免前端重命名与 Broker 更新状态相互覆盖；运行快照由 Broker 单写。
7. 首版不自动回放历史 ANSI，不承诺重连后的完整画面；日志和屏幕状态恢复单独设计。
8. 发布路径定为单文件、Deb/RPM、软件源分阶段推进，当前不创建发行包、签名密钥、托管域名或发布自动化。

详见 [架构设计](architecture.md) 与 [协议草案](protocol.md)。

### 验证中发现并修正

- **macOS PTY 非阻塞读取**：最初只对库返回的 FD 设置 `O_NONBLOCK`，读取会出现 `EAGAIN`。检查依赖和 Go 的 FD 包装实现后，改为用 `F_DUPFD_CLOEXEC` 复制描述符，在非阻塞状态下重新构造 `os.File`，注册到 Go 的 poller。补充 resize 后读取 deadline 仍生效的测试，防止未来 attach 清理时阻塞。
- **测试目录权限**：测试框架提供的子目录权限不满足存储的私有目录约束。改为在临时父目录中由 Store 创建专用 state 子目录，保留生产代码的权限拒绝规则。
- **验证脚本清理**：自动审批拒绝了一次带 `rm -rf` 的临时目录清理命令，理由是禁止 `rm -f` 风格操作。改用仅删除已知空目录的 `rmdir` 后完成 TUI 冒烟验证；没有遗留审批需求。

- **独立 Broker**：同一二进制隐藏子命令重新执行、新 session、独立 stdio、readiness pipe、每任务排他锁、PTY 和子会话所有权。

- **存储**：跨进程 catalog flock、同名竞争保护、原子 JSON、spec/runtime 分离、路径规范化、UTF-8/NUL 校验、1 MiB 元数据大小限制、权限/owner/symlink 检查。

### 补充修正

1. macOS `/dev/tty` 不能直接依赖 Go kqueue 的文件读取。改用 native poll 与非阻塞 syscall，最长 100 ms 检查取消，先等待读取循环退出再恢复 termios，避免坏 FD 和遗留 reader。
2. 主动 detach 原先先发 Detach 帧可能与服务端 EOF 竞速，造成错误退出码。改为先选择本地 detach 结果，再通过关闭 Socket 释放控制权。
3. 新建前台应用在 attach 前输出的提示符以及极快退出输出可能丢失。增加一次性的有界启动缓冲及已结束任务的输出/退出码处理；启动缓冲合并小块，避免极碎输出填满通道导致死锁。
4. `stop` 等待 Broker 锁释放后返回，避免刚记录 exited 就执行 delete 的竞争；已删除任务及真实文件错误另外处理，不无限轮询。
5. 状态根目录规范化，避免 macOS `/var` 与 `/private/var` 等祖先路径别名造成 Socket 哈希不一致。
6. 存储写入与读取使用一致的 1 MiB 上限，拒绝超大 spec 后不影响已有任务列表。
7. 独立 nFPM 配置的 content source 环境展开需要 `expand: true`，根据本地 nFPM 源码核实并修正后，Deb/RPM 两种独立打包均通过。

- 连接前及断开时从有界输出日志提取白名单模式，写入当前实例的私有 terminal.json 检查点。正常连接的字节转发路径不解析或重画应用输出。

- 初始捕获的首次前台输出不重复恢复；日志扫描在订阅 live 输出之前进行，避免扫描时间造成高速输出队列溢出；恢复过程中的 SIGWINCH 也同步处理。
